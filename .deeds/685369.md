# Retain startup-stalled GUI sessions for compositor recovery

The supervisor in `src/session.rs::serve` terminates its children if the GUI
receiver has not answered `hello` within 60 seconds. A license, update, or other
startup dialog that prevents the managed plugin from loading can therefore
disappear before an operator investigates it. `screenshot` and `input` use the
supervisor and compositor independently of GUI RPC, but only while that session
is still alive.

Separate the CLI's bounded startup wait from the owned GUI's lifetime. Keep a
startup-stalled session available for explicit screenshot/input recovery or
`stop --force`, with readiness reported as unknown/not ready. Preserve prompt
failure and cleanup when a child actually exits.

Verify a startup modal that blocks plugin initialization beyond the old
60-second deadline: capture it, dismiss it through compositor input, and confirm
the same session becomes usable. Also verify explicit stop and actual startup
process failures still clean up owned children.
