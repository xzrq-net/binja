# Retain request artifacts until stop or start

User decision, 2026-09-13: keep every request's artifacts for the session and
clean them up on `stop` and on `start`, instead of deleting the artifact
directory when a record leaves the 64 newest finished results.

Background: results over 16 KiB are delivered as a path under
`<state>/artifacts/<id>/`, and in the stress trial that path expired within
two seconds at 33 calls/s, so the subject treated every result as write-once
and copied it immediately. Pruning inline stdout/stderr/result from the
in-memory record can stay bounded at 64; the `output_pruned` flag then only
matters for re-fetching an old record, which is a recovery path. Update the
guide's retention paragraph accordingly. While there, print the "Accepted:"
receipt on the human path only when the request is actually queued behind
something; on the running path it is a long line of noise on every call.
