# Add a start flag that disables the GUI startup deadline

The supervisor in `src/session.rs::serve` terminates its children if the GUI
receiver has not answered `hello` within 60 seconds. Decision: the deadline
stays at 60 seconds by default. A license, update, or other startup dialog that
prevents the plugin from loading takes the compositor down with it, so on-site
debugging needs a way to keep that session alive.

Add `start --no-startup-deadline` (or an equivalent flag) that passes through to
the supervisor and skips the readiness deadline. With it, a startup-stalled
session stays up with readiness reported as not ready, so `screenshot`, `input`
and `stop --force` work against it. Children that actually exit must still fail
promptly and clean up. Mention the flag in the guide's stuck-GUI paragraph.

Today the failing `start` says "Session startup exited (...); inspect
<state>/logs." The GUI's stdout/stderr are in `logs/binaryninja.log` and the
supervisor's in `logs/supervisor.log`; the CLI does not relay them inline. Name
both files in that error so an agent knows where to look before reaching for the
flag.

Verify with a startup modal that blocks plugin initialization beyond 60 seconds:
without the flag, the session fails and cleans up; with it, capture the modal,
dismiss it through compositor input, and confirm the same session becomes usable.

Closed: Added start --no-startup-deadline, named both startup logs, and documented recovery. Verified real 60/70-second deadlines with a Qt modal before receiver startup, same-generation recovery through compositor input, force-stop, and both child-exit cleanup paths. Nix build, seven Rust tests, and the installed smoke suite passed; evidence is recorded in docs/log.md.
