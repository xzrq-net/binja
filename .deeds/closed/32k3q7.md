# Extend API lookup with member listing

Build on `api search` and `api show`. Property writability and enum members
are already delivered (nvafxz). The remaining gap: `api search` matches
declarations and docstrings, it is not member enumeration, and inheritance is
not followed. Trial subjects guessed `Function.set_user_name` and
`Function.size`.

Stage 1: `api members CLASS [--match]`, a compact static listing of a class's
members with signature, the owning class for inherited members, and the
existing property metadata. Distinguish "no such member" from "not in the
index" (native UI classes, C extension types). Stays offline: no GUI, no
license, no CLI import of Binary Ninja.

Stage 2, deferred until a concrete lookup fails: runtime introspection for
extension classes. Never evaluate every property during enumeration.

Verify a large class (BinaryView), inherited members, and missing or ambiguous
symbols. Update the packaged guide from concrete mistakes; do not create
another API manual.

Closed: Stage 1 delivered: offline api members CLASS [--match TEXT] with C3 inheritance from the static index, unindexed bases reported explicitly. Stage 2 (runtime introspection) stays deferred until a concrete lookup fails.
