# Add editing commands with native undo grouping

Plausible, not essential: rename and comment through `py` worked in every
trial. The value is in type and local-variable edits, where name-only variable
selection and judging success from stale HLIL are error-prone, and in an undo
affordance.

Commands, in order of expected use: `rename FUNCTION NEW_NAME`,
`comment ADDRESS|FUNCTION TEXT`, `proto FUNCTION 'C prototype'`,
`retype FUNCTION VARIABLE TYPE`, `declare --file types.h`. Each edits, waits
for analysis, and reads back what it changed (name, comment, prototype,
variable type), reporting changed or no-op. No preview mode, no snapshot
diffing, no rollback framework: that is bn's machinery and a decided non-goal.

Undo, the inobtrusive graft: Binary Ninja records undo entries between
`bv.begin_undo_actions()` and `bv.commit_undo_actions(id)`; `bv.undo()` reverts
the last committed entry. Wrap each request's execution (py and typed edits
alike) in one begin/commit so a request is one undo unit, and add
`undo [--target]` calling `bv.undo()`. First verify in the GUI process whether
edits made from the worker thread outside begin/commit are already recorded,
and whether commit from the worker is safe. If grouping needs the UI thread or
behaves surprisingly, record that and skip the wrapper rather than building
around it. Undo entries interleave with human edits in the same GUI; `undo`
reports the entry's summary text so the caller sees what it reverted.

Recipe first: before implementing `proto` and `retype`, add a tested guide
recipe (identify the native variable, apply the type,
`update_analysis_and_wait`, read back the type and affected HLIL). Promote to
commands from that recipe.

Closed: rename/comment/proto/retype/declare/undo as typed command scripts with native readback and changed/no-op; execute() groups each retained-target request in one native undo entry (commit in finally, undo excluded). Recipe and undo experiments in docs/log.md 2026-09-13.
