# Review token efficiency of CLI framing and metadata

User request, 2026-09-13: review what each command costs the model in tokens,
especially framing and metadata, without squeezing it to the bone. A few
hundred requests per session (249 in the stress trial) make per-call overhead
add up.

Candidates seen in the trials: two stderr receipt lines per call (`Request ID`
plus a long `Accepted:` summary with target snapshot, phase, elapsed); the
completion summary repeating the ID, handle, view type, and full path; `open`
and `save` echoing the target twice; `api show` printing the store path and
docs path on every hit; JSON records carrying `target_snapshot` with nine
fields on every response. Measure with the stress scripts, propose a leaner
default with `--json` and `--verbose` keeping the full record, and keep the
guide honest about what is printed.

## Implementation handoff

Accepted rendering contract: use ASCII separators (two spaces or semicolons).
Keep pre-submission request ID; human Accepted receipt only for non-null
waits_behind. Avoid repeated ID/path/snapshot metadata on completion. Artifact-
backed streams show path and bytes instead of preview; verbose and JSON retain
full records. api show retains a source:line pointer by default, moving docs
URL and version to verbose. Implement the per-command design-turn output
proposals with the Rust client in B.

Closed: Implemented the accepted lean defaults with ASCII separators, source pointers, queued-only receipts, artifact paths, and full verbose/JSON records. Representative py output fell from 456 to 109 bytes (187 to 55 o200k_base proxy tokens); comparison and limits recorded in docs/log.md.
